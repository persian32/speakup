- **화면·디자인·코드가 `index.html` 하나에 다 있다.** 빌드도, 설치할 것도 없다.

## 2026-10-12 (월) — 프롬프트 교체 · 배포

### 바꾼 것

- **피드백 항목**: 문법·표현·발음·억양 → **발음의 정확성 / 발음의 유창성** 두 항목. 항목마다 장점, 단점 및 개선 방향을 **최대 2개씩, 근거가 있는 것만**. 출력 형식 고정
- **"가장 어려웠던 점" 질문 삭제** — AI에게 묻지 않고 학생이 **수행평가 학습지에 직접** 쓴다
- **ChatGPT 자동 입력 한도 3,500 → 8,000** — 새 프롬프트의 링크가 약 6,000자
- 화면 문구 "문법·표현 피드백 받기" → "발음 피드백 받기", 맨 위 안내문, 페이지 설명(meta description), README

### 흐름

선생님 프롬프트 초안 검토 → 수정할 곳 10개를 번호로 정리 → 전부 반영한 최종 문구 확정 → 앱에 적용 → 로컬 확인 → 푸시(바로 배포) → 로그인된 ChatGPT로 직접 녹음해 확인(정상)

### 초안에서 고친 10곳

1. 역할: AI가 학생 역할을 하던 것 → "너는 영어 말하기 코치, 나는 고2 학생"
2. "음성 파일을 토대로" → "받아쓴 문장과 측정값을 토대로" (앱이 자동으로 채움)
3. 장점·단점 4개씩 → 최대 2개, 근거 있는 것만
4. 발음 정확성: 받아쓴 문장 속 R/L·F/P·끝소리 단어 + **어색하게 받아써진 단어**를 근거로
5. 유창성: 측정된 속도·긴 멈춤 횟수·억양을 근거로. 앱은 멈춤이 *몇 번*인지만 보내고 *어디서*인지는 안 보낸다
6. "실제 녹음에서" → "받아쓴 문장에서"
7. "파일을 확인할 수 없으면 알려 줘" 삭제 → "소리를 들은 게 아니니 '틀렸다' 대신 '이렇게 하면 좋아'로, 인식 오류는 표시만"
8. "스크립트" → "말한 문장"
9. 출력 형식 칸 4개 → 2개
10. 마지막 반복 문단 삭제

### 오늘 내린 판단

- **초안의 틀은 살리고 표현만 앱에 맞게.** 그대로 넣으면 AI가 "음성 파일을 확인할 수 없습니다"라고 답하거나 듣지 않은 발음을 지어낸다
- **개수를 강제하지 않는다.** 짧은 말하기에서 근거 있는 특징은 많지 않다. 4개씩 채우라고 하면 지어낸 내용이 들어간다
- **짧게 줄인 문구 대신 긴 최종 문구.** 대신 자동 입력 한도를 올렸다

### 헷갈렸던 것과 교훈

- 처음에 "ChatGPT 자동 입력이 안 된다"고 한 건 ChatGPT가 아니라 **앱 코드의 3,500 제한** 때문이었다. 직접 열어 보니 ChatGPT는 5,985자 링크도 받았다 → "안 된다"고 말할 때는 **누가 막는지**까지 확인한다
- 확인용 브라우저의 오류는 ChatGPT 로그인·로봇 확인 문제였다. 로그인 여부는 프롬프트가 먹히는지와 상관없다
- ChatGPT 링크(`?q=`)는 문구를 채우기만 하는 게 아니라 **바로 전송**한다
